# Analysis of the five must-validate parameters

| Parameter | Property/category | Why static evidence is insufficient | Benignly observable prerequisites | Compatibility evidence | Incompatibility evidence | Inconclusive evidence |
|---|---|---|---|---|---|---|
| `SKB_SEND_SIZE` | Allocator and socket-buffer geometry | Source proves requested length and checks, but not EZE4 runtime cache/fragment placement or overlap outcome. | Memory totals, page size, exposed slab/socket limits can describe prerequisites. | Future authorized actual-consumer evidence establishes the intended allocation and path state with this size. | Actual-consumer evidence consistently establishes a different cache/fragment outcome or safe path failure attributable to the size. | Matching page size, ZG3 success, or generic slab listings without the consumer. |
| `SLIDE_WAIT_NSEC` | Scheduler timing and race ordering | Static control flow cannot establish scheduling latency or when the required waiter state is reached. | CPU topology, scheduler policy exposure, load, clock source. | Actual-path traces show the required waiter state is established before timeout across the defined validation scope. | Actual-path traces show timeout/state ordering prevents the path. | Benign userspace timing or one unrelated scheduler sample. |
| `SLIDE_REQUEUE_ARM_USEC` | Scheduler timing and race ordering | The delay's adequacy depends on live inter-thread/kernel ordering. | CPU topology, load, affinity capabilities, clock source. | Actual-path ordering evidence shows requeue arming occurs in the required window. | Evidence shows systematic ordering outside that window attributable to the delay. | Ordinary sleep accuracy or system load alone. |
| `FOPS_ROUTE_COARSE_DELAY_USEC` | Coarse scheduler/race timing | Source defines a delay but cannot predict EZE4 scheduling and route-state timing. | CPU topology, frequency/scheduler exposure, load. | Actual-path trace shows the coarse delay places execution in the required state window. | Trace shows the configured delay consistently misses the window. | ADB latency, userspace sleep timing, or source equality. |
| `FOPS_ROUTE_FINE_DELAY_TICKS` | Fine counter-tick sweep and race ordering | Static analysis cannot establish counter-to-event timing or whether the listed sweep covers the live window. | Counter/clock-source identity and CPU topology may be observed. | Actual-path timing evidence shows at least one listed tick offset reaches the required state under the defined scope. | Evidence shows the relevant window lies outside or is incompatible with the sweep. | Clock frequency alone or a successful unrelated operation. |

All five require L3 evidence to validate the value. L1/L2 observations can characterize prerequisites only. No final value or test procedure is proposed.
