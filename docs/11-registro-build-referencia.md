# 11. Reference Downstream Build Record

## Reproducibility Result

On August 22, 2026, the Wi-Fi kernel published for `X510XXU3BXDG`, commit `9a752a83347461b3785711760ba925fcabea3071`, was successfully built:

- Kernel release: `5.15.123-g9a752a833474-dirty`;
- ARM64 `Image` measuring 38,361,600 bytes;
- Target base DTB: `s5e8835.dtb`;
- SM-X510 overlays: `r00`, `r01`, and `r04`;
- 282 modules processed with `modpost`, signing, `strip`, and `depmod`;
- LTO/BTF linking and Samsung FIPS integrity procedure completed;
- Final exit code 0.

On August 23, `scripts/build-all-reference.sh` was fully re-executed: ext4 checkout, idempotent patch application, kernel compilation, module build, BusyBox build, two initramfs profiles, DTBO packaging, candidate repacking, and AVB validation all finished with exit code 0. Manifests were subsequently re-verified. Following hardening, the extended host test suite contains 88 tests covering OSRC U11 guards, tree comparisons, safety/adversarial tests, DTS semantics, and image utilities.

After pinning Kbuild user, host, version counter, and timestamp to the source commit, two consecutive link runs produced bit-identical `Image` outputs with SHA-256 `16ec4fdba131639f41d3ccd8c724be561c7e7e11cccf6c99539d193ad910cd9c`. This demonstrates incremental reproducibility within the VM while preserving the module signing key; a clean rebuild from an empty disk must also pin the autogenerated module signing key before claiming universal bit-for-bit reproducibility.

The `dirty` suffix is expected: it reflects the patch series applied over the published vendor commit. It does not indicate archive corruption. Outputs and logs are preserved in `artifacts/kernel/wifi/reference-dist` and `artifacts/logs/reference-kernel-build.log`.

This milestone validates the compilation toolchain and pipeline, **not compatibility with EZE4**. The target tablet runs Android 16 / U12, while this source baseline is Android 14 / U3.

The kernel source cannot be reliably built on standard macOS APFS: Linux includes filenames that differ only in case, and an APFS checkout exhibits false modifications from collision handling. For this reason, intermediate objects and build trees live under `$HOME/gts9fe-work` inside the VM.

## Identified Defects and Reproducible Fixes

| Phase / Symptom | Root Cause | Reproducible Fix |
|---|---|---|
| APFS exhibits uncommitted git modifications | Case-insensitive host filesystem | Clone and build inside Lima ext4 native disk |
| `sysbusy` and `filemap` fail on C prototypes | Deprecated C syntax accepted by legacy Samsung toolchain | Explicit return types and Clang 21 compatibility (`0002`) |
| KVM references uninitialized `clidr` | Strict Clang dataflow analysis | Safe explicit initialization (`0002`) |
| `exynos-devfreq.h` omits return type | Legacy K&R C declaration | Explicit `int` return type (`0003`) |
| Wi-Fi, RCD, and cpupm drivers contain invalid declarations | Implicit types and variable use before error checks | `bool`/`int` return types and proper sequencing (`0004`) |
| Mali QoS omits return type | Implicit C type declaration | Explicit `bool` return type (`0005`) |
| UFS fails to locate `s5e8835` headers | Missing `TARGET_SOC=s5e8835` | Export variable matching upstream `build_kernel.sh` |
| devfreq reads uninitialized `buf` | Incomplete vendor fallback | Remove broken fallback path (`0006`) |
| SM5714 charger uses uninitialized property | Incomplete error handling flow | Initialize property prior to read (`0008`) |
| Samsung test code violates `-mgeneral-regs-only` | Deliberate crash / FPSIMD test module | Exclude test module from bring-up build (`0008`) |
| Novatek driver returns errno from interrupt handler | Return domain mismatch (`irqreturn_t` vs `int`) | Return `IRQ_HANDLED` (`0009`) |
| Type-C driver compares incompatible enums | data-role enum vs port-type enum | Use `TYPEC_PORT_SRC/SNK` (`0010`) |
| `dtbs` terminates without building tablet overlays | Makefile uses deprecated `always` Kbuild rule | Request and verify each DTBO target explicitly |
| Distribution directory contains hundreds of unrelated DTBs | `dtbs` builds all ARM64 boards | Select and publish only `s5e8835.dtb` and three X510 overlays |
| Installed modules consume 499 MiB | Unstripped debug symbols | `INSTALL_MOD_STRIP=1`; reduces footprint to ~51 MiB |
| BusyBox fails in `tc.c` with modern headers | CBQ was removed from modern kernel UAPI | Rescue miniconfig excluding `tc` |
| BusyBox builds as dynamic ELF | `allnoconfig` ignores boolean miniconfig fragments | Apply options post-configuration and verify each symbol |
| Classic repack scripts expect combined kernel+ramdisk | Android v4 header separates `boot` and `init_boot` | Two dedicated repack scripts |
| Relative path to `magiskboot` breaks upon `cd` | Binary path resolved after directory change | Resolve absolute path before creating temporary workdir |
| ARM64 Linux ELF cannot execute on macOS ARM64 | Different binary ABI and executable format | Execute official tool inside Lima VM |
| Build failure leaves obsolete artifact in dist directory | Outputs not invalidated upon failure | Clean target dist directory before starting rebuild |
| Output path aliases stock, overlay, or manifest | Script `rm`/repack could destroy its own input | Resolve canonical paths and reject aliases prior to modification |
| Malformed DTBO passes superficial checks | Missing validation of header, table, payload, and FDT bounds | Validate offsets, overlaps, sizes, and magic before publishing |
| Incoherent boot / AVB header appears valid | Unbounded `header_size` and `original_image_size` | Verify format minimums and assert offsets reside within image bounds |
| AVB reports expected failure on oversized partition image | Only checked textual output of `avbtool` | Reject empty candidate or image exceeding stock partition size |

Every kernel modification resides in `patches/downstream/wifi`; `apply-patches.sh` was run repeatedly and confirmed all patches as cleanly applied. It also passed `git diff --check`.

## Repackaging and AVB Verification

The target firmware utilizes Android boot image header v4:

- `boot`: Kernel of 39,356,928 B, no ramdisk;
- `init_boot`: Legacy LZ4 ramdisk of 2,486,802 B, no kernel;
- `vendor_boot`: Vendor ramdisk of 18,077,432 B, DTB of 239,652 B, and two table fragments.

Using official Magisk v30.7 `magiskboot`, image copies were repacked and re-extracted. The extracted kernel and CPIO byte-match their inputs. AOSP `android16-release` `avbtool` verifies the stock image; on repacked candidates it validates the VBMeta structure but rejects the partition hash. This is the expected result: candidate images retain a Samsung digital signature over pre-modification contents. Candidates are designated `UNSIGNED` and must not be flashed.

Scripts perform a secondary extraction to confirm byte-for-byte fidelity of the payload. `verify-avb-candidates.sh` simultaneously requires that stock passes verification, that candidate RSA4096 signature/structure remains parseable, and that the modified payload digest is rejected. Any different AVB failure is not accepted as the expected failure.
