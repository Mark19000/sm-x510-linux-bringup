# 12. Reproducible Comparison: U3 ↔ U11 ↔ EZE4

This chapter defines the comparison gate for the acquired Android 16 OSRC delivery. The SM-X510 U11 source consists of overlay `X510XXSBDZB4` applied on top of base `X510XXU8DYJ4`, running Linux kernel 5.15.180. It is maintained strictly separate from U3 (`X510XXU3BXDG`) and does not replace the exact OSRC package for `X510XXUCEZE4`.

The kernel observed in the stock EZE4 boot image is `5.15.189-android13-3-33478785`, built with Clang `r450784d`. Therefore, kernel releases, Android API levels, and bootloader binary counters are recorded separately; that a U11 branch compiles does not prove equivalence to EZE4.

## Host-Only Comparison Command

With the complete U11 composite extracted on ext4, execute from repository root or guest environment:

```sh
./scripts/compare-osrc-trees.sh \
  --u3-dir sources/wifi-kernel \
  --u11-dir /path/to/extracted-OSRC-U11 \
  --eze4-dir artifacts/stock/dt \
  --output reports/generated/u11-osrc
```

The comparator reads only the two source directories and the EZE4 DTS files. It does not download OSRC archives, does not launch a VM, and does not wait for `.part` downloads; `.part` fragments appearing inside a tree are ignored. Passing a path directly ending in `.part` is rejected to prevent mistaking an incomplete download for reproducible source. The current report was generated against the exact composite and resides in `reports/generated/u11-osrc/`. See chapter 14 for interpretation.

Output comprises `comparison.json` (complete data, SHA-256 digests, and path sets) and `comparison.md` (auditable summary). Publication uses a temporary directory and replaces only an existing output generated by this tool; any read, parse, or validation error leaves the prior report untouched. Nothing is written to `sources/` or `artifacts/`.

## Comparison Categories

The inventory separates four categories, which may overlap (for instance, `drivers/foo/Kconfig` belongs to both `drivers` and `configs`):

| Category | Examples | Produced Evidence |
|---|---|---|
| `dts` | `*.dts`, `*.dtsi` | U3/U11 relative paths, added, removed, and changed hashes |
| `drivers` | Any file under `drivers/` | Path presence and content; prioritizes ABI and peripheral code |
| `configs` | `Kconfig*`, `*_defconfig`, `.config*`, `*.cfg`, `configs/` | Symbol and fragment diffs requiring maintainer review |
| `build_scripts` | `Makefile`, `Kbuild`, `build*.sh`, `build.config*`, `Android.bp/mk`, `*.mk` | Rule, toolchain, and packaging discrepancies |

In each category, "changed" denotes that the SHA-256 digest of the identical relative path differs. "U3/U11-only" denotes that the path is absent in the opposing tree; it does not imply that a driver is required or safe.

## EZE4 DTS Matching Matrix

If `--eze4-dir` contains decompiled `.dts`/`.dtsi` files produced by `tools/dtbo_extract.py` or `tools/fdt_scan.py`, the JSON and Markdown append a row per EZE4 DTS containing:

- Best-match U3 and U11 candidates, ranked by `compatible` strings, `dtbo-hw_rev` ranges, and path tokens;
- Semantic comparisons for U3 ↔ U11, U3 ↔ EZE4, and U11 ↔ EZE4 via `tools/dts_semantic_diff.py`;
- Classification status, count of material differences, unresolved external references, and phandle renumberings.

Ambiguous automatic matches are marked `UNMAPPED` and display the top five candidate scores. To pin a specific revision, supply an external mapping JSON (without altering source trees):

```json
[
  {
    "eze4": "overlays/overlay-02-id-00000000-rev-00000000.dts",
    "u3": "arch/arm64/boot/dts/samsung/gts9fewifi/gts9fewifi_eur_open_w00_r04.dts",
    "u11": "arch/arm64/boot/dts/samsung/gts9fewifi/gts9fewifi_eur_open_w00_r04.dts"
  }
]
```

Pass via `--dts-map map.json`; U3/U11 paths are relative to their tree roots and the EZE4 path matches the report entry name. Binary `.dtb` files are inventoried, but cannot be semantically compared without decompilation; the report states this explicitly. An `INCONCLUSIVE` or `DIFFERENT (INCOMPLETE)` status is never converted into equivalence.

## Interpretation and Next Gate

This matrix isolates divergences before porting patches: Device Tree, drivers, Kconfig flags, and build rules must be evaluated together. In particular, U11 reference `X510XXSBDZB4`/`X510XXU8DYJ4` and stock EZE4 kernel 5.15.189 must not be conflated due to version proximity. Prior to building images for the physical device, exact EZE4 OSRC checkout, delivery commit/hash, defconfig, toolchain, and verified DT/DTBO correspondences must be established.
